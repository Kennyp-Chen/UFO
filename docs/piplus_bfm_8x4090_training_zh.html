2. 8×4090 服务器准备

2.1 硬件与目录

  • 8 张 RTX 4090，每张 24 GiB；单机 8 卡，GPU 间通常通过 PCIe/NCCL 通信。
  • 建议至少 128 GiB 系统内存、16 个以上 CPU 核和 200 GiB 以上本地 NVMe 空间；多次实验需预留更多空间。
  • 专家数据只有约 372 MiB，训练前复制到节点本地 NVMe，避免 8 个 rank 并发读取网络盘。
  • 工作目录必须放在高速盘。8 卡 checkpoint 会保存 8 份 rank-local replay buffer；磁盘容量按 buffer 大小近似线性增长。
容量参考：源仓库单卡 256 万 transition 的 buffer checkpoint 约 11 GiB；八卡同配置仅 buffer 就约 88 GiB，模型和优化器还会额外占用数 GiB。本手册用每卡 128 万作为 24 GiB 4090 的保守起点。

5. 正式训练

5.1 4090 起始参数

参数起始值含义
--num-envs512每张 GPU 512，总并行环境 4096
--buffer-size1280000每张 GPU 的 replay 容量，总有效容量 1024 万
--num-env-steps192000000八卡合计的全局采样预算，不要再乘 8
--checkpoint-every-steps3200000按全局步数触发
--update-z-every-step100FB 默认值
--num-agent-updates不覆盖保留 FB preset 的 16，先建立可比较基线
若单卡峰值低于 20 GiB，可先把 --buffer-size 提到 1920000，再考虑增加环境数；每次只改一个参数并重新做短训。若 OOM，先降 buffer 到 960000，再降环境数到 384 或 256。

5.2 使用 tmux 启动

tmux new -s piplus-bfm
cd /local_nvme/ufo/src

export PIPLUS_MOTION_DIR=/local_nvme/ufo/data/piplus
export UFO_CACHE_DIR=/local_nvme/ufo/cache
export CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7
export NCCL_NVLS_ENABLE=0
export PYTHONUNBUFFERED=1

# 可选 W&B：先执行 uv run wandb login，并设置自己的 entity。
export WANDB_ENTITY=your_entity
RUN_DIR=/local_nvme/ufo/runs/piplus_bfm_fb_8x4090_seed4728

./run_train.sh \
  --agent fb \
  --robot-config configs/robots/piplus_bfm.yaml \
  --data-manifest configs/data/piplus_lafan.yaml \
  --gpu-ids all \
  --num-envs 512 \
  --num-env-steps 192000000 \
  --buffer-size 1280000 \
  --checkpoint-every-steps 3200000 \
  --update-z-every-step 100 \
  --seed 4728 \
  --work-dir "$RUN_DIR" \
  --use-wandb \
  --wandb-run-name piplus_bfm_fb_8x4090_seed4728 \
  2>&1 | tee "$RUN_DIR.launch.log"

退出 tmux 而不中止训练：按 Ctrl-B，再按 D。恢复终端：tmux attach -t piplus-bfm。

不要复用 smoke 的 work-dir。发现 checkpoint 时训练入口会自动恢复；正式实验必须使用新的空目录，防止意外继承调试模型或 replay buffer。

6. 监控、故障定位与恢复

6.1 运行中检查

watch -n 2 'nvidia-smi --query-gpu=index,memory.used,utilization.gpu,temperature.gpu,power.draw --format=csv,noheader'
tail -f /local_nvme/ufo/runs/piplus_bfm_fb_8x4090_seed4728/train_log.txt
watch -n 30 'df -h /local_nvme; du -sh /local_nvme/ufo/runs/piplus_bfm_fb_8x4090_seed4728 2>/dev/null'

cat /local_nvme/ufo/runs/piplus_bfm_fb_8x4090_seed4728/checkpoint/train_status.json
cat /local_nvme/ufo/runs/piplus_bfm_fb_8x4090_seed4728/checkpoint/distributed_sync.json
现象处理
CUDA OOM停止全部 rank；新建 work-dir；buffer 先降到 960000，再按需把 envs 降为 384/256
NCCL timeout / 某 rank 消失检查 dmesg、GPU Xid、PCIe 拓扑和温度；确保 8 个进程一起退出后再重启
NaN / nonfinite保留日志和 checkpoint，停止训练；检查最近 reward、动作幅度、接触力和数据 hash，不要直接续跑
磁盘快速增长确认 rank buffer 数量为 8；扩大磁盘或降低 buffer；不要在写 checkpoint 时删除文件
GPU 利用率长期不均定位最慢 rank、CPU 饱和、热降频和数据盘延迟；任一慢 rank 会拖住同步更新

6.2 断点恢复

使用与原运行完全相同的 8 卡数量、GPU 可见顺序、机器人、数据、环境数和 buffer 参数，重新执行正式命令并指向同一个 --work-dir。程序会读取 checkpoint/train_status.json、模型和 train_rank_0..7。

test -s "$RUN_DIR/checkpoint/train_status.json"
for rank in 0 1 2 3 4 5 6 7; do
  test -d "$RUN_DIR/checkpoint/buffers/train_rank_${rank}" || exit 1
done

# 然后原样重跑第 5.2 节命令。日志应出现 Loading the agent。
分布式 checkpoint 不能自动更换 world size。缺任一 rank buffer、改成 1/4 卡或改变 rank 映射时，不应直接恢复；应新开实验或显式迁移 buffer。

CUDA_VISIBLE_DEVICES=0 \
PIPLUS_MOTION_DIR=/local_nvme/ufo/data/piplus \
uv run python -m humanoidverse.tracking_inference \
  --model-folder "$RUN_DIR" \
  --robot-config configs/robots/piplus_bfm.yaml \
  --data-manifest configs/data/piplus_lafan.yaml \
  --dataset piplus_lafan \
  --device cuda:0 \
  --headless \
  --disable-dr \
  --disable-obs-noise \
  --save-mp4 \
  --motion-list 0

确认输出视频不是空白，机器人姿态、左右关节和根朝向正确，无持续穿地或明显爆炸。量化验收还应记录 tracking 指标并和固定 seed 的前一 checkpoint 比较。
