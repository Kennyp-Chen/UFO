5090 SHM illegal memory access 定位与修复

结论
- 根因定位为 NCCL 2.26.2 在 RTX 5090/Blackwell + 当前驱动组合下的 SHM 兼容性问题。
- 不是 /dev/shm 容量、单卡故障、NUMA 分组或 PCIe/IOMMU 硬件错误。

关键证据
- 原 NCCL 2.26.2：任意 GPU 对在首次 64 MiB SHM all-reduce 即报 CUDA illegal memory access。
- /dev/shm 可用约 189 GiB；dmesg 无 NVRM/Xid/AER/DMAR 错误。
- NCCL 2.27.7：同一环境 2 卡、8 卡 SHM all-reduce 均通过；8 卡 PyTorch dist.all_reduce 也通过。

已完成修复（5090）
- 虚拟环境 `/data/hejunfu/UFO-main/.venv` 的 `nvidia-nccl-cu12` 已升级到 2.27.7。
- `/data/hejunfu/train_env.sh` 已将 `NCCL_SHM_DISABLE` 默认值改为 0。
- 当前仍保持 `NCCL_P2P_DISABLE=1`、`NCCL_IB_DISABLE=1`，因为该机当前未验证出可用 P2P/IB 路径。

验收结果
- NCCL runtime: 2.27.7+cuda12.9
- 8 卡 SHM all-reduce：通过
- 8 卡 PyTorch NCCL smoke：通过，所有 rank 返回 all_reduce=36.0

持久化配置
- 5090 项目的 `pyproject.toml`/`uv.lock` 已通过 uv override 固定 `nvidia-nccl-cu12==2.27.7`；执行 `uv sync` 不会再回退到 2.26.2。
